# WD FD1793 / 1818VG93 (КР1818ВГ93) Floppy Disk Formatter/Controller — datasheet as the die behaves

This is the WD FD179X-02 datasheet (May 1980) rewritten for the **WD FD1793** and its Soviet counterpart the
**1818VG93**, so that every statement matches the chip as reverse-engineered from the die: the transistor-level
schematic and the microcode ROM dump by deathsoft, the gate-level schematic and the decoded microprogram by titus.
The original text was transcribed page by page; wherever it is wrong, self-contradictory, vague or incomplete, it is
replaced here by the behaviour of the die. The microprogram itself is in [Appendix B](#appendix-b-microprogram).

The 1818VG93 repeats the FD1793 design. **The only known behavioural difference is in the A1 / C2 sync mark
detectors** (channel bit 13 is not compared, section 14). Everything else corrected here is poor documentation in
the WD datasheet, not a property of the Soviet chip: the same corrections apply to the FD1793.

How the numbers were obtained: the logic and the microcode give the sequences exactly; times were measured on the
gate-level model of the die (and on the synthesizable model that is checked against it microword by microword), at
CLK = 1 MHz unless stated otherwise. The model also ran in an FPGA with TR-DOS and real 3.5″ drives.

Notation: `/X` — active low signal. **[DS]** marks a place where the WD datasheet is wrong, self-contradictory or
silent about what the chip does; **[VG93]** the one known difference of the 1818VG93 from the FD1793 (bit 13 of the
A1 / C2 detectors). All of them are listed in [Appendix A](#appendix-a-corrections-to-the-wd-fd179x-02-datasheet).

Electrical characteristics and package data cannot be recovered from a die reverse; they are given as in the WD
datasheet and marked as such.

## 1. Features

- FM (IBM 3740, single density) and MFM (IBM System 34, double density), selected by `/DDEN`.
- Soft-sectored formats, sectors of 128, 256, 512 and 1024 bytes, 1 to 255 sectors per track, tracks 0 to 255.
- Automatic track seek with verification; single and multiple sector read and write with automatic sector search;
  whole-track read and write (formatting).
- True (non-inverted) 8-bit bidirectional data bus, as the FD1793.
- Side compare flags in Type II commands (no side select output: the side is selected outside the chip).
- Programmable step rate, head load control with external head load timing input.
- Write precompensation outputs EARLY / LATE.
- Address mark detection, FM / MFM encoding and decoding, CRC-CCITT generation and checking on chip.
- Read gate output RG and VFO enable `/VFOE` for an external data separator; the data separator itself is external
  (inputs RCLK and `/RAW READ`).
- Controlled by a microprogram in an on-chip ROM of 256 words × 19 bits ([Appendix B](#appendix-b-microprogram)).

**1818VG93 = FD1793**: true data bus, RG on pin 25, no side select output, FM and MFM, the same design; the only
known behavioural difference is bit 13 of the A1 / C2 detectors. The FD1791 (inverted bus), FD1792/4 (FM only) and
FD1795/7 (side select output, `b` flag) variants of the WD datasheet do not apply.

## 3. Organization

The chip consists of the processor interface, the data path (shift register, data register, CRC, serial ALU,
address mark detectors), the drive interface, and a microprogrammed controller: a 256 × 19 bit ROM sequenced by an
8-bit program counter, counters CNT1 (8 bits) and CNT2 (4 bits), and a step rate timer.

Internally the chip runs on two non-overlapping clocks F1 and F2 derived from CLK (outside read mode) or from
RCLK (in read mode). One microword is executed per F1 period: 4 CLK periods in MFM, 8 in FM (4 µs / 8 µs at
1 MHz), which is one data bit cell of the disk (two channel cells: the clock and the data cell). All times below that are given in "F1 periods" scale with this.

**Data Shift Register (DSR)** — assembles bytes from the channel bits read from the disk and shifts bytes out to the
encoder when writing.

**Data Register (DR)** — holding register between the DSR and the processor; holds the target track for Seek.

**Track Register (TR)** — current head track; incremented / decremented by the serial ALU (one pass takes 57 F1
periods, about 7 bytes of disk time); compared with the track number of ID fields. **[DS]** Writing it is never
blocked, also while a command uses it; a write that lands during a serial ALU pass stores the AND of the written
value and the shifting register contents.

**Sector Register (SR)** — target sector; the same serial structure and the same write behaviour as TR. Loaded
with 01 by /MR.

**Command Register (CR)** — the command being executed; write only. **[DS]** Not protected by BUSY: see
section 4.4.

**Status Register (STR)** — read only; meaning depends on the command type (section 11).

**CRC logic** — CRC-CCITT, G(x) = x¹⁶ + x¹² + x⁵ + 1, over the address mark and the field up to the CRC bytes.
Preset to FFFF before writing a field; when reading, preset so that the result is that of the field with its
address mark sequence (MFM: CRC of A1 A1 A1 = preset 968B before the last A1; FM: preset FFE0 at the mark).

**Serial ALU** — compares (TR with DR or with the ID track number, SR with the ID sector number), increments and
decrements TR / SR bit-serially.

**Address mark detectors** — compare the last 16 channel bits with the mark patterns: MFM A1 (4489h),
MFM C2 (5224h), the A1-to-mark junction (2555h), FM marks with clock C7 and the FM index mark (clock D7). Each
detector is enabled only by the microwords that wait for it. **[VG93]** The A1 and C2 detectors ignore channel
bit 13 (a defect of the die, the only known difference from the FD1793, section 14).

## 4. Processor interface

### 4.1 Registers

| A1 A0 | Read (/RE) | Write (/WE) |
|---|---|---|
| 0 0 | Status | Command |
| 0 1 | Track | Track |
| 1 0 | Sector | Sector |
| 1 1 | Data | Data |

### 4.2 Write latency and the shared input latch

**[DS]** All registers are written through one shared input latch: the byte is captured from DAL at /WE and
moved into the target register two F1 periods later (8 µs MFM / 16 µs FM at 1 MHz). Consequences:

- a register written by /WE reads back its new value only after these two F1 periods;
- two register writes closer than two F1 periods disturb each other (the second byte replaces the first in the
  latch). Keep at least 8 µs (MFM) / 16 µs (FM) between register writes at CLK = 1 MHz.

### 4.3 DRQ and INTRQ

- **Read:** DRQ is set when a byte is moved from the DSR to the DR and cleared by reading the DR. If the next byte
  arrives before the DR was read, it overwrites the DR and Lost Data is set; the read goes on to the end of the
  field.
- **Write:** DRQ is set when the DR is moved into the DSR and cleared by writing the DR. If the DR is not written in
  time, the DSR shifts out zeros (a byte of 00 is written) and Lost Data is set; the command goes on (but see the
  first byte rules of Write Sector and Write Track).
- DRQ is cleared asynchronously by /RE or /WE of the data register (no clock delay).
- DRQ also appears as status bit 1 of Type II / III status.
- One byte is 8 F1 periods: 32 µs (MFM) / 64 µs (FM) at 1 MHz between DRQs.
- **INTRQ** is set at the end of every command (except Force Interrupt D0, section 10) and by the Force Interrupt
  conditions; it is cleared by reading the status register or writing the command register. **[DS]** The clear is
  immediate (the INTRQ flip-flop is a latch transparent in the F1 high phase), not after up to 3 µs.

### 4.4 Command register and BUSY

- **[DS]** BUSY (status bit 0) becomes visible 4 F1 periods after the command write (16 µs MFM / 32 µs FM at
  1 MHz, including the input latch). A status read right after the command write still shows BUSY = 0 and the old
  status.
- **[DS]** The command register is loaded on every write, BUSY or not. A command is *started* only if the
  microprogram sees the write while it waits for a command (idle loop). A command written while another one runs:
  - is not started after the running command ends;
  - but its bits are in the command register at once, and the running command branches on them from then on. Up to
    ~31 µs (MFM) / ~60 µs (FM) after a Type I command was written, the new bits fully replace it; a Type II command
    tests bit 7 after ~8 µs. Later, single flags change the running command (writing a V bit turns a running Seek
    into a Seek with verify);
  - Force Interrupt (1101 xxxx) is recognised from the register contents at any time (section 10).
- The Track and Sector registers are not protected either (section 3).

### 4.5 Status validity after a command write

Status is valid 4 F1 periods after the command write (section 4.4). The WD note "14 µs MFM / 28 µs FM at 2 MHz,
doubled at 1 MHz" does not match: 16 µs (MFM) / 32 µs (FM) at 1 MHz.

### 4.6 Master reset

While /MR is low: the command register is loaded with 03 (Restore, rate 3), the sector register with 01, the
program counter with 000; status bit 7 (Not Ready) reads 1 (it is ORed with /MR). After /MR goes high a Restore is
executed regardless of READY (no verify, rate 3: 30 ms at 1 MHz). /MR does not reset the CLK divider: its phase at
power on is undefined. INTRQ is active after power on until the status is read or a command is written.

## 5. Floppy disk interface

### 5.1 Clock and density

CLK = 1 MHz for 5.25″ and 3.5″ drives (2 MHz for 8″, all times below halve). `/DDEN` selects MFM (0) or FM (1);
the internal F1 period is 4 CLK periods in MFM and 8 in FM. CLK may change frequency between commands (turbo boards
switch 1 ↔ 2 MHz); all chip times follow it.

### 5.2 Head positioning

Step period by the r1 r0 field (Type I commands), the same in FM and MFM:

| r1 r0 | /TEST = 1, CLK 1 MHz | /TEST = 1, CLK 2 MHz | /TEST = 0, CLK 1 MHz, MFM | /TEST = 0, CLK 1 MHz, FM |
|---|---|---|---|---|
| 0 0 | 6 ms | 3 ms | 352 µs | 704 µs |
| 0 1 | 12 ms | 6 ms | 376 µs | 752 µs |
| 1 0 | 20 ms | 10 ms | 388 µs | 776 µs |
| 1 1 | 30 ms | 15 ms | 416 µs | 832 µs |

**[DS]** With /TEST = 0 the step timer is bypassed and the step period is the length of the microprogram step loop
(including the 57-period serial TR update), so it doubles in FM; the WD table (368/380/396/416 µs, independent of
/DDEN) does not apply.

- **STEP**: one F1 period, 4 µs (MFM) / 8 µs (FM) at 1 MHz.
- **DIRC** is set long before the first step pulse: between the direction update and STEP there are the serial TR
  update (57 F1 periods ≈ 228 µs MFM) and the wait for the step timer — far more than the 12 µs of the WD text.
- **Head settle**: 15 periods of the step timer = **30 ms at 1 MHz (measured 29.9 ms) in both MFM and FM**, after the
  last step when V = 1, and before HLT is sampled when E = 1 in Type II / III. With /TEST = 0 it shrinks to about
  0.4 ms (MFM) / 0.9 ms (FM).
- **TG43** is updated from TR at the beginning of every command (before any stepping) and in the verify phase of
  Type I: TG43 = 1 when TR > 43. It is a level, valid after the update, not "only during read and write".

### 5.3 Head load

- Type I: h = 1 sets HLD at the beginning, h = 0 clears it at the beginning (also with V = 1); V = 1 sets HLD after
  the last step, then the settle time, then HLT is awaited.
- h = 1, V = 0: HLD is set, HLT is not sampled, no settle time.
- Type II / III: HLD is set at the beginning (after the READY test); E = 1 adds the 30 ms settle time; then HLT is
  awaited.
- HLD drops after 15 index pulses in the idle state (BUSY = 0), or at the start of a Type I command with h = 0 (with
  V = 1 it is set again for the verify).
- Status bit 5 of Type I status is HLD AND HLT.
- HLT is typically driven by a one shot fired by the HLD rising edge (head engage time of the drive, 30–100 ms), or
  tied high.

### 5.4 Reading

**Data separator inputs.** RCLK is a square wave with one half period per channel cell (MFM: 2 µs half periods at
1 MHz, a 4 µs period = one data bit; FM: 4 µs half periods). Each `/RAW READ` pulse (a flux transition) sets the
latch of the RCLK half period it falls into; at the end of each half period the latch is read as one channel bit
and cleared. The polarity of RCLK does not matter, its phasing relative to the pulses does: a pulse must fall well
inside a window. A pulse still low at the end of a window sets the latch again for the next window. In read mode
the internal F1 / F2 clocks follow RCLK.

**Read gate RG and address mark search** (Type II, Read Address):

- MFM: RG is set after a preamble of 4 bytes of 00 or FF; three A1 marks (4489h, missing clock) must then be found
  within 16 bytes, otherwise RG drops and the search starts again. The three A1 need not be consecutive: other
  bytes between them enter the CRC. After the third A1 the mark junction (2555h) is looked for within 11 bytes; it
  also matches after any byte ending in xxxxx001, so the byte before the mark need not be a missing-clock A1.
- FM: RG is set after 2 bytes of 00; the mark (clock C7) must be found within **11 bytes** (WD text: 10).
- The address mark byte is classified by its upper 6 bits: 111111xx (FC–FF) = ID field, 111110xx (F8–FB) = data
  field. F8 and F9 are deleted data marks (status bit 5 = 1), FA and FB normal data marks.
- RG is not used by Read Track.

**/VFOE** (pin 33 while WG = 0) goes low while the chip is reading data from the disk (read mode), after the head is
loaded and the settle time has expired; it is an open drain output (pull-up 10 kΩ).

### 5.5 Writing

- **WG** is turned on only after the first data byte was written into the DR in answer to DRQ (Write Sector: the
  check happens 8 bytes after the first DRQ, section 8.3; Write Track: 3 bytes after the command, section 9.3).
- **WD** pulses: in MFM a pulse lasts exactly the CLK low phase (500 ns with a 1 MHz square wave; a 30 / 70 % CLK
  gives 300 / 700 ns); in FM one CLK period (1 µs at 1 MHz). One pulse per flux transition, in 2 µs (MFM) / 4 µs
  (FM) cells at 1 MHz; intervals 4, 6, 8 µs in MFM.
- **[DS]** WD is produced by gates from the cell timing; it is not a clean flip-flop output. Boards that drive a
  drive from it through fast logic should resynchronise it.
- **EARLY / LATE** are valid for the whole WD pulse. MFM: a pulse is marked LATE when the data pattern around it is
  0 1 1 (the bit before is 0, the next one 1), EARLY for 1 1 0, and the clock pulses between zero bits accordingly;
  FM uses the same outputs for the half-cell timing. TG43 is not combined with them inside the chip: the board
  enables precompensation (usually only when TG43 = 1) and delays the pulses (EARLY: 0, nominal: d, LATE: 2d).
- **/WPRT** low at the start of any write command terminates it at once with Write Protect set and INTRQ.
- **/WF** low while writing (pin 33 is an input when WG = 1) terminates the command with Write Fault (status bit 5).

### 5.6 READY

Type II and III commands test READY right after the command is started: READY = 0 ends the command at once with
INTRQ (status bit 7 = 1). Type I commands ignore READY. Status bit 7 is the inverse of READY ORed with /MR.

### 6.2 Flags

| Flag | Bit | Commands | Meaning |
|---|---|---|---|
| h | 3 | I | 1: load the head at the beginning; 0: unload at the beginning (V = 1 loads it again for the verify) |
| V | 2 | I | 1: verify on the destination track |
| r1 r0 | 1, 0 | I | step rate (section 5.2) |
| u | 4 | Step, Step In, Step Out | 1: update TR on every step |
| m | 4 | II | 1: multiple sectors |
| S | 3 | II | side to compare (with C = 1): 0 = side 0, 1 = side 1 |
| E | 2 | II, III | 1: 30 ms head settle (1 MHz) before HLT is sampled |

| a0 | 0 | Write Sector | 0: data mark FB; 1: deleted data mark F8 |
| I3…I0 | 3–0 | IV | interrupt conditions (section 10) |

### 6.3 Common start of every command

**[DS]** Writing any command except Force Interrupt starts the same entry: BUSY is set and **all** error flags are
cleared — CRC error, Record Not Found / Seek Error, Write Fault / record type, Write Protect, Lost Data, and DRQ —
for every command type (the WD flowcharts clear different subsets per command). The status is switched to the
Type I layout for Type I commands and to the Type II / III layout for the others. TG43 is updated.

## 7. Type I commands

Restore, Seek, Step, Step In, Step Out. The rate field r1 r0 sets the step period (section 5.2).

### 7.1 Flow

```
TYPE I:
  common start (6.3)
  if h = 1: set HLD  else: clear HLD
  if Step In:  DIRC = 1; goto STEP_U
  if Step Out: DIRC = 0; goto STEP_U
  if Step:     goto STEP_U                    (DIRC unchanged)
  if Restore:  TR = FF; DR = 00                (then as Seek)
SEEK_LOOP:                                     (Seek, Restore)
  if TR = DR: goto VERIFY
  DIRC = (DR > TR)
  TR = TR + 1 if DIRC else TR - 1              (serial, 57 F1 periods)
  goto PULSE
STEP_U:
  if u = 1: TR = TR + 1 if DIRC else TR - 1
PULSE:
  if DIRC = 0 and /TR00 = 0: TR = 0; goto VERIFY      (no pulse at track 0 when stepping out)
  issue one STEP pulse
  wait one step period (r1 r0)
  if Seek or Restore: goto SEEK_LOOP
VERIFY:
  if V = 0: clear BUSY, INTRQ; end
  set HLD; wait 30 ms (settle); wait HLT = 1
  CNT = 6
  loop:
    every index pulse: CNT = CNT - 1; when CNT = 0: set Seek Error; clear BUSY, INTRQ; end
    read the next ID field
    if its track = TR:
      if CRC error: set CRC Error; continue loop
      clear CRC Error; clear BUSY, INTRQ; end
    (track mismatch: continue loop)
```

### 7.2 Restore

TR is loaded with FF and DR with 00, then the command runs as a Seek to track 0: TR is decremented before every
step pulse, and when /TR00 goes low (stepping out) TR is set to 0 without a further pulse.

**[DS]** If /TR00 never goes low: after 255 step pulses TR has counted down from FF to 00 = DR and the seek ends
normally — **no Seek Error** (status 00). With V = 1 the verify then fails and sets Seek Error. (WD: Seek Error
after 255 pulses.)

Restore is also executed when /MR goes high (section 4.6).

### 7.3 Seek

TR must hold the current track, DR the target. TR is stepped towards DR one step per period until they are equal;
TR is updated before each pulse. Stepping out with /TR00 low sets TR = 0 and ends the stepping.

### 7.4 Step, Step In, Step Out

One step pulse in the previous direction (Step), in (Step In, DIRC = 1) or out (Step Out, DIRC = 0). With u = 1 TR
is incremented / decremented before the pulse. Stepping out while /TR00 is low gives no pulse and sets TR = 0
(also with u = 0). Then the step period elapses and the verify follows if V = 1.

### 7.5 Verify

After the settle time and HLT, ID fields are read until one has the track number of TR and a correct CRC.
**[DS]** A track mismatch does not end the command (the WD text says it does, the WD flowchart says it does
not): the search goes on. An ID with the right track and a CRC error sets CRC Error and the search goes on; a
correct one clears CRC Error and ends the command. **[DS]** The search ends with Seek Error after **6** index
pulses (6 or 7 counted from the command write when the index falls into the settle time); WD text: 4 revolutions,
WD flowchart: 5 index holes. Verify does not compare the side.

## 8. Type II commands

Read Sector and Write Sector. Load the Sector Register before writing the command.

### 8.1 Flow (common part)

```
TYPE II:
  common start (6.3)
  if READY = 0: clear BUSY, INTRQ; end
  set HLD
  if E = 1: wait 30 ms (settle)
  wait HLT = 1
  TG43 update
  if Write Sector and /WPRT = 0: set Write Protect; clear BUSY, INTRQ; end
SEARCH:
  CNT = 6
  loop:
    every index pulse: CNT = CNT - 1; when CNT = 0: set Record Not Found; clear BUSY, INTRQ; end
    find an ID field (preamble, A1 A1 A1 / FM mark, mark FC..FF)
    if ID track != TR: continue
    if ID sector != SR: continue
    if C = 1 and side(ID) != S: continue        side(ID) = 0 if the ID side byte is 0, else 1
    take the length code (low 2 bits of the ID length byte)
    if ID CRC error: set CRC Error; continue
    clear CRC Error
    Read Sector -> READ_DATA, Write Sector -> WRITE_DATA
```

**[DS]** Timeout: **6** index pulses for any starting position (WD: 4 revolutions / 5 index holes).
**[DS]** Side compare: the side byte of the ID counts as side 0 only when it is 0; any other value (1, 2, 3, …)
is side 1 (WD: the LSB of the side byte). **[DS]** Without C the side is not compared (the WD flowchart draws the
compare unconditionally).

Sector length by the low 2 bits of the ID length byte: 00 = 128, 01 = 256, 10 = 512, 11 = 1024 bytes.

### 8.2 Read Sector

```
READ_DATA:
  find the data mark (F8..FB) in the window: MFM byte 25..48, FM byte 7..23 after the last ID CRC byte
  if not found: set Record Not Found; clear BUSY, INTRQ; end
  status bit 5 = 1 for F8 / F9 (deleted), 0 for FA / FB
  for every byte of the field: move it to DR, set DRQ (Lost Data if DR was not read)
  read the 2 CRC bytes
  if CRC error: set CRC Error; clear BUSY, INTRQ; end        (also with m = 1)
  if m = 1: SR = SR + 1; goto SEARCH
  clear BUSY, INTRQ; end
```

**[DS]** Data mark window (measured): the data mark must be the byte 25…48 (MFM) / 7…23 (FM) after the last ID
CRC byte, i.e. GAP II of 9…32 bytes of 4E before the 12 bytes of 00 and the three A1 (MFM), or 0…16 bytes before
the 6 bytes of 00 (FM). The WD text "within 43 / 30 bytes" is wrong at both ends. Internally the microprogram skips
16 bytes of GAP II and then searches 16 bytes; a longer gap cannot be bridged by chains of 00 / FF bytes (the byte
counter has 4 bits).

With m = 1 the sectors SR, SR + 1, … are read until a sector is not found (Record Not Found, SR = the missing
number) or a Force Interrupt; a CRC error ends the command.

### 8.3 Write Sector

```
WRITE_DATA:
  skip 2 bytes of GAP II; set DRQ                    first DRQ 2.00 bytes after the last ID CRC bit
  skip 8 bytes
  if DR was not written: set Lost Data; clear BUSY, INTRQ; end
  skip 1 byte
  MFM: skip 11 bytes; WG on; write 12 x 00; write A1 A1 A1 (missing clock); write mark FB (a0 = 0) or F8 (a0 = 1)
  FM:  WG on; write 6 x 00; write mark FB / F8 with clock C7
                                                     WG on 22.38 (MFM) / 11.38 (FM) bytes after the last ID CRC bit
  for every byte of the field: DR -> DSR, set DRQ; write the byte
      (DR not written in time: Lost Data, a byte of 00 is written; the command goes on)
  write the 2 CRC bytes
  write 1 byte FF; WG off during its last bit
  if m = 1: SR = SR + 1; goto SEARCH
  clear BUSY, INTRQ; end
```

The CRC of a written data field covers A1 A1 A1 and the mark (MFM) or the mark (FM). The trailing FF byte protects
the CRC from the write turn-off; WG drops during its last bit, so on the disk it reads back as FF or FE.

## 9. Type III commands

### 9.1 Read Address

```
  common start; READY test; set HLD; [E: 30 ms]; wait HLT; TG43 update
  CNT = 6
  loop:
    every index: CNT = CNT - 1; when CNT = 0: set Record Not Found; clear BUSY, INTRQ; end
    find an ID field
    6 bytes (track, side, sector, length, CRC1, CRC2) -> DR, DRQ for each
    SR = track number of the ID
    if CRC error: set CRC Error
    clear BUSY, INTRQ; end
```

The timeout is 6 index pulses (this one agrees with the WD flowchart).

### 9.2 Read Track

```
  common start; READY test; set HLD; [E: 30 ms]; wait HLT; TG43 update
  wait for the index pulse
  until the next index pulse:
    shift channel bits into the DSR; every 8 data bits, or at once when a sync mark is detected:
        move the DSR to DR, set DRQ (Lost Data if DR was not read)
  clear BUSY, INTRQ; end
```

- Reading starts at the leading edge of an index pulse and ends at the next one. No CRC is checked, RG is not
  used, no side compare.
- **Synchronisation:** MFM on the A1 (4489h) and C2 (5224h) clock patterns, FM on the marks with clock C7 and the
  index mark with clock D7. A detected mark forces a byte boundary, so a revolution gives somewhat more than 6250
  (MFM) bytes, typically ~6300.
- **[VG93]** The A1 and C2 detectors ignore channel bit 13: 6489h and 7224h (not valid MFM) synchronise too.
- **False synchronisation (design flaw of the whole FD179X family):** the C2 pattern occurs in normal data. Any even
  byte followed by 29h contains it, and so does the pair "00, A1 with missing clock" at the clock phase. Therefore
  the first A1 of each A1 A1 A1 group comes out as a junk byte, and an ID reads as `… A1 A1 FE …`. Data fields
  written by Write Sector may be in another bit phase than the IDs written by Write Track and read as garbage.
- Status: Lost Data, DRQ, BUSY; bits 3 and 4 stay 0.

### 9.3 Write Track

```
  common start; READY test; set HLD; [E: 30 ms]; wait HLT; TG43 update
  if /WPRT = 0: set Write Protect; clear BUSY, INTRQ; end
  set DRQ (at once)
  wait 3 byte times
  if DR was not written: set Lost Data; clear BUSY, INTRQ; end
  wait for the index pulse
  until the next index pulse:
    DR -> DSR, set DRQ; write the byte, interpreting control bytes (table below)
    (DR not written in time: Lost Data, a byte of 00 is written; the command goes on)
  clear BUSY, INTRQ; end
```

**[DS]** The first byte must be in the DR within 3 byte times after the command (as the WD flowchart), not "by the
index pulse" (WD text).

Control bytes:

| DR (hex) | MFM (/DDEN = 0) | FM (/DDEN = 1) |
|---|---|---|
| 00–F4 | write in MFM | write with clock FF |
| F5 | write A1 with the clock between bits 4 and 5 missing; preset the CRC (after an F5 the CRC is that of A1 A1 A1) | write A1 with clock FF (no missing clock); preset the CRC as in MFM **[DS]** |
| F6 | write C2 with the clock between bits 3 and 4 missing | write C2 with clock FF **[DS]** |
| F7 | write the 2 CRC bytes | write the 2 CRC bytes |
| F8–FB | write in MFM | write with clock C7; preset the CRC to FFFF before it |
| FC | write in MFM | write with clock D7 (no CRC preset) |
| FD | write in MFM | write with clock FF (no CRC preset) **[DS]** |
| FE | write in MFM | write with clock C7; preset the CRC to FFFF before it |
| FF | write in MFM | write with clock FF |

**[DS]** F5 and F6 in FM are not "not allowed": the F5 / F6 detectors do not depend on /DDEN, they substitute A1 /
C2 and F5 presets the CRC; only the missing clock is MFM-only. **[DS]** FD in FM is a plain byte (the WD table is
right, the WD flowchart that groups FD with the marks is wrong).

As a consequence, F5–F7 (MFM) and F7–FE (FM) cannot be written as data by Write Track; CRCs must be generated by F7.

## 10. Type IV command: Force Interrupt

`1101 I3 I2 I1 I0`. It is recognised from the command register contents at any time.

- **During a command:** the command is abandoned at the next microword that allows interruption (marked EI in the
  microprogram; the latency depends on where the command is), BUSY is cleared, the other status bits are left as
  they are.
- **Without a command:** the common start is executed (all error flags cleared, Type I status layout), then BUSY is
  cleared.
- **D0 (I3…I0 = 0):** no interrupt.
- **Conditions** (checked in the idle loop after the command, repeatedly, until another command is written):
  - I0: READY 0 → 1 transition;
  - I1: READY 1 → 0 transition;
  - I2: every index pulse — INTRQ is set again at **every** index pulse;
  - I3: immediate — INTRQ is set again on every F1 period, so reading the status does not clear it; only writing
    another command does.
- **[DS]** After D8 (and any Dx), INTRQ is cleared by writing **any** next command, not only D0.

## 14. Behaviour the WD datasheet does not describe (summary)

1. **[VG93] A1 / C2 detectors ignore channel bit 13** (the comparator input is not connected on the die) — the only
   known difference from the FD1793. 6489h and 7224h (not valid MFM) are taken as A1 / C2 in every command that
   waits for them. Game copy protections rely on it; a WD FD1793 does not sync on them.

The rest is common to the FD1793 and the 1818VG93, only missing or wrong in the WD datasheet:

2. **False C2 synchronisation in Read Track**: every "even byte, 29h" and every "00, A1" boundary.
3. **Command register not protected by BUSY**; Track and Sector registers writable at any time (AND with the
   shifting value during a serial pass).
4. **Shared input latch**: register writes need 2 F1 periods between them.
5. **Restore without /TR00**: 255 pulses, no Seek Error unless V = 1.
6. **Timeouts are 6 index pulses** (verify, ID search, Read Address).
7. **Side compare**: ID side byte 0 = side 0, any other value = side 1.
8. **Verify continues on a track mismatch** until the timeout.
9. **All error flags cleared at every command start**, including CRC before Read Track and Write Track.
10. **F5 / F6 in FM Write Track** write A1 / C2 (clock FF) and F5 presets the CRC.
11. **Force Interrupt conditions repeat** (I2 every index, I3 every F1 period) until another command is written.
12. **INTRQ is active after power on.**
13. **WD is combinational**: its pulse width follows the CLK low phase; resynchronise it on boards with fast logic.
14. **TEST mode** step periods follow the microprogram loop and double in FM.
15. **+12 V must be present** whenever +5 V is (substrate bias generator).
16. **Address mark classes**: FC–FF = ID mark, F8–FB = data mark (F8 / F9 deleted).

## Appendix B. Microprogram

The controller is a microprogrammed sequencer. The ROM (256 words × 19 bits) was dumped from the die by deathsoft
(transistor-level reverse) and decoded by titus. Files in [microcode/](microcode/):

- `vg93-microcode-rom.hex` — the ROM image, one 19-bit word per line (`$readmemh`);
- `vg93-microcode-rom.csv` — every word split into its fields with the mnemonic;
- `vg93-microprogram-v0.2.txt` — the complete commented listing by titus (Russian);
- `vg93-microcommands.txt` — the list of micro-operations (Russian);
- `vg93-command-sequences-v0.2.txt` — the microword sequences of every command (Russian).

### B.1 Microword format

```
  Hi    Cmd     Mod  R/W  Imm
  18-16 15-10   9-7  6-4  3-0
```

| Bits | Field | Meaning |
|---|---|---|
| 18–16 | Hi | upper jump address bits / extra condition |
| 15–10 | Cmd | micro-operation (6 bits; 59 codes used) |
| 9–7 | Mod | program counter / counter control: load CNT1, load CNT2, byte strobe, EI (interruptible word) |
| 6–4 | R/W | data path mode: READ, READS, WRITE, JUMP |
| 3–0 | Imm | immediate: low jump address, counter constant, or the bit to test |

The program counter advances by 1, or by 2 when a test condition skips the next word; jumps load the low and high
halves of the PC separately. A large comparator (29 inputs) forms the jump condition from the micro-operation and
the tested signals. Words marked EI let a Force Interrupt abandon the command (vector 002).

### B.2 Vectors

| Address | Function |
|---|---|
| 000 | start of a command (cold / warm start, new command from the host) |
| 001 | write fault (/WF = 0 while writing) → set Write Fault |
| 002 | idle loop: wait for a command; Force Interrupt lands here |
| 003 | idle with the head loaded: at most 15 index pulses (CNT1 = 15), then unload (004) |

### B.3 Counters

- **CNT1** (8 bits): revolutions (decremented by each index pulse outside writing) and 16-byte blocks of a sector
  field (length = 4 · 2^(N+1) blocks, the first one 15 bytes). Search timeout 6 index pulses, idle head unload 15.
- **CNT2** (4 bits): bytes and delays, decremented by the byte strobe or by the step timer. It is decremented at the
  end of every loop also from 0, so after a loop it holds 15.
- **Step timer**: an 8-bit LFSR with a period of 249 F1 periods (≈ 2 ms at 1 MHz in FM; in MFM, where the F1 period
  is half as long, a ÷2 stage makes it 2 ms as well), so the step rates are equal in both densities: 3 / 6 / 10 / 15
  timer periods per step.
- **Serial ALU**: TR / SR increment and compare, 57 F1 periods per pass.
